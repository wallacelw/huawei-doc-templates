== Introdução

[.badge]#Novo#

[.objectives]
====
[.general-objective]#Validar a implantação da Plataforma de Dados do Huawei Cloud para o
ambiente POC, garantindo que todos os serviços principais (DataArts Studio, MRS,
OBS, VPC) estejam provisionados corretamente, acessíveis e funcionando conforme
especificado na arquitetura da solução.#

*Pré-requisitos:*

- Conta Huawei Cloud com privilégios de administrador IAM na região `sa-brazil-1`.
- VPC, sub-rede e grupos de segurança já criados pela equipe de infraestrutura.
- Instância DataArts Studio (Dayu) provisionada e licenciada.
- Cluster MRS implantado com a pilha de componentes necessária (HDFS, YARN, Spark, Hive).
- Bucket OBS criado e acessível com a política IAM designada.
- Ambiente de execução de testes com conectividade de rede ao Console do Huawei Cloud.
- Ferramentas CLI `latexmk` e `terraform` instaladas localmente.
====

=== Escopo dos Testes

.Escopo dos testes por domínio.
[.hutable]
|===
| Domínio | O Que Deve Ser Observado

| Arquitetura da Plataforma | Serviços principais estão implantados, saudáveis e acessíveis via API do Console.
| Engenharia de Dados | Pipelines do DataArts Studio conseguem ingerir, transformar e carregar dados no armazenamento de destino.
| Armazenamento de Dados | Buckets OBS e HDFS do MRS aceitam escritas/leituras com permissões corretas.
| Segurança | Políticas IAM, isolamento VPC e regras de grupo de segurança impõem o controle de acesso pretendido.
|===

=== Pré-condições e Preparações

- Todos os recursos de infraestrutura devem ser provisionados via Terraform e a saída do `terraform apply` deve apresentar zero erros.
- O cluster MRS deve estar no estado *Executando* antes da execução de qualquer caso de teste de engenharia de dados.
- Arquivos de dados de teste (CSV/JSON) devem ser carregados no bucket OBS designado antes da execução dos pipelines.
- Cada testador deve ter uma conta IAM pessoal com a função *Dayu_User* atribuída no DataArts Studio.
- Regras de firewall de rede devem permitir TCP 22 (SSH) e TCP 443 (HTTPS) de entrada a partir da sub-rede de execução de testes.

[.note]#Certifique-se de que o ambiente de execução de testes esteja configurado com o fuso horário `America/Sao\_Paulo` (GMT-3) para que os registros de data/hora nos logs estejam alinhados com o Console do Huawei Cloud.#

[source,bash]
----
# Verificar se as ferramentas CLI estão instaladas
terraform version
obsutil version
kubectl version --client
----

TIP: Utilize `terraform plan` antes de `terraform apply` para
visualizar as alterações de infraestrutura e evitar modificações indesejadas de recursos.

=== Método de Aceitação

.Critérios de aceitação.
[.hutable]
|===
| Resultado | Explicação

| Atende | O caso de teste passa completamente — o comportamento observado corresponde ao resultado esperado sem desvios.
| Atende com ressalvas | O caso de teste foi executado com sucesso, mas com restrições, dependências ou configuração adicional (documentadas em Observações).
| Não atende | O caso de teste falha — o comportamento observado não corresponde ao resultado esperado. Um relatório de defeito deve ser registrado.
| Não testado | O caso de teste não foi executado — a execução permanece pendente e deve ser agendada.
|===

\begin{testcase}{Verificar aplicação de política IAM nos buckets OBS}
  \testobjective{Confirmar que as políticas IAM restringem corretamente o acesso
    ao bucket OBS — usuários autorizados podem ler/escrever enquanto usuários
    não autorizados são negados, e a política do bucket segue o princípio
    do menor privilégio.}
  \testscope{Aplicação de política IAM; Controle de acesso OBS; Validação de menor privilégio}
  \begin{testprerequisites}
    \teststep{Bucket OBS \inlinecode{poc-datalake-raw} existe com a política IAM designada.}
    \teststep{Dois usuários IAM de teste: um com função \textbf{OBS\_ReadWrite}, outro sem permissões OBS.}
    \teststep{CLI \inlinecode{obsutil} configurada para ambos os usuários.}
  \end{testprerequisites}
  \begin{testprocedure}
    \teststep{Usando o usuário autorizado, carregar um arquivo de teste em \inlinecode{poc-datalake-raw}}
    \teststep{Usando o usuário autorizado, baixar e verificar o conteúdo do arquivo}
    \teststep{Usando o usuário não autorizado, tentar carregar um arquivo — verificar se a requisição é negada (HTTP 403)}
    \teststep{Usando o usuário não autorizado, tentar listar objetos no bucket — verificar se a requisição é negada}
    \teststep{Revisar a política do bucket no Console em \menu{Console, Object Storage Service, Bucket Policies} e confirmar que concede apenas as permissões pretendidas}
  \end{testprocedure}

  \begin{code}[bash]
# Usuário autorizado — carregar e verificar
obsutil cp test-file.txt obs://poc-datalake-raw/test-file.txt
obsutil ls obs://poc-datalake-raw/ -limit=5

# Usuário não autorizado — esperar erros 403
obsutil cp test-file.txt obs://poc-datalake-raw/unauthorized.txt
obsutil ls obs://poc-datalake-raw/
  \end{code}

  \begin{testexpected}
    \teststep{Usuário autorizado consegue carregar e baixar com sucesso.}
    \teststep{Usuário não autorizado recebe HTTP 403 nas operações de carregamento e listagem.}
    \teststep{Política do bucket concede apenas as permissões de leitura/escrita pretendidas às funções designadas.}
  \end{testexpected}
  \testresult{\testresultbadge{Fail}}
  \testremarks{Verificar os logs do Cloud Trail se a negação de acesso não for retornada conforme esperado — pode haver herança de política do projeto ou domínio.}

  \note{Alterações em políticas IAM podem levar até 5 minutos para propagar. Aguardar antes de retestar após modificar uma política.}
\end{testcase}
